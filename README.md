# 바이럴배너 인사이트 자동 입력

업체가 보낸 인사이트 스크린샷을 읽어 콘텐츠RD 시트의 날짜 열에 자동으로 기입합니다.
업체마다 캡처 형식이 달라도 됩니다 (앱/PC, 안드로이드/아이폰, 인스타/틱톡 모두).

## 사이트로 쓰는 게 기본입니다

배포 방법과 사장님이 하실 일은 **[배포하기.md](배포하기.md)** 에 정리해 뒀습니다.
아래 CLI(`run_folder.py`)는 디버깅용 보조 수단입니다.

  - 업체용   `https://주소/?v=<토큰>`  — 로그인 없음, 올리는 즉시 판독 결과 표시
  - 담당자용 `https://주소/`           — 비밀번호. 판독·검토·시트 반영이 전부 여기서 됩니다

## 로컬 설치 (개발용)

```bat
pip install -r requirements.txt
setx ANTHROPIC_API_KEY "sk-ant-..."
```

API 키는 console.anthropic.com → API Keys 에서 발급합니다. 발급 후 새 터미널을 엽니다.

## CLI 로 폴더 판독 (디버깅용)

**먼저 구글 인증 없이 테스트하세요.** 결과만 CSV로 나오고 시트는 건드리지 않습니다.

```bat
python run_folder.py --folder "..\루나앤코코\0823" --vendor 루나앤코코 --scope day ^
    --rows "..\실제인사이트_260823.xlsx"
```

결과가 맞으면 구글시트에 연결합니다.

```bat
:: 시트에서 후보를 읽고 _배너인사이트_자동수집 탭에만 기록 (RD 시트는 안 건드림)
python run_folder.py --folder "..\루나앤코코\0823" --vendor 루나앤코코 --scope day --sheet

:: 확정 건을 RD 시트 날짜 열에 실제 기입
python run_folder.py --folder "..\루나앤코코\0823" --vendor 루나앤코코 --scope day --sheet --commit
```

### --scope 를 반드시 맞추세요

| 값 | 뜻 | 해당 업체 |
|---|---|---|
| `day` | 이 폴더는 **해당 업로드일** 게시물만 담고 있음 | 루나앤코코 (`0823/0823-채널명.png`) |
| `window` | 추적중 게시물이 **여러 날짜 섞여** 있음 | 업크루, 굿띵투유, 동후작가 |

`window` 인데 `day` 로 돌리면 대부분 매칭실패가 납니다.

### 상태값

| 상태 | 의미 | 조치 |
|---|---|---|
| `확정` | 행이 확정됨. `--commit` 시 기입됩니다 | 없음 |
| `검토필요` | 값은 읽었지만 어느 행인지 확실하지 않음 | **사람이 확인** — 기입되지 않습니다 |
| `매칭실패` | 시트에서 해당 행을 못 찾음 | 미등록 소재인지 확인 |
| `판독실패` | 숫자를 읽을 수 없음 | 캡처 다시 받기 |
| `대상아님` | 인사이트 화면이 아님 (피드/그래프) | 무시 |

`검토필요`는 절대 자동 기입하지 않습니다.

## 사이트 (app.py)

```bat
streamlit run app.py
```

| 화면 | 주소 | 내용 |
|---|---|---|
| 업체 | `?v=<토큰>` | 드래그 업로드 → 즉시 판독 결과 → 잘못된 건 그 자리에서 재업로드 |
| 담당자 | `/` | **판독·반영** / **수집 현황** / **업체 링크** 3개 탭 |

담당자 탭에서 이미지를 올려 판독하고, `확인 필요` 건은 행을 직접 골라 반영합니다.
`확정`만 자동 반영되고 `확인 필요`는 사람이 지정해야 들어갑니다.

토큰은 Secrets 의 `[VENDORS]` 또는 `config.py` 의 `VENDORS` 에서 바꿉니다.
Secrets 가 있으면 그쪽이 우선입니다 (공개 저장소에 토큰을 두지 않기 위함).

### 월요일 처리

월요일은 금·토·일 합산본 **1개**가 들어옵니다. 반영 시
**"측정을 건너뛴 중간 날짜 열에 직전 측정값 복사"** 를 켜두면 (기본 켜짐)
금·토 열에 직전 누적값이 복사되고 일요일 열에 새 값이 들어갑니다.
0을 넣으면 증분값이 왜곡되기 때문입니다. 게시물이 아직 없던 날짜는 비워 둡니다.

### 배포

**[배포하기.md](배포하기.md)** 를 보세요. 클릭 경로까지 단계별로 적어뒀습니다.
무료 등급은 유휴 시 앱이 잠들어 업체가 처음 열 때 20~30초 걸립니다.

## 구글시트 연결

배포 시에는 Secrets 로 넣습니다 ([배포하기.md](배포하기.md) 4번).
로컬에서는 서비스 계정 JSON을 `service_account.json` 으로 이 폴더에 두고,
**RD 시트를 그 서비스 계정 이메일에 편집자로 공유**하면 됩니다.
없으면 CSV 모드로만 동작합니다.

## 검증

```bat
python selftest.py
```

2026-08-24에 사람이 직접 판독한 45장의 값을 넣어 매칭 엔진만 시험합니다
(API 호출 없음). **45/45 통과**가 정상입니다.

`config.py` 의 매칭 점수를 건드렸다면 반드시 다시 돌려보세요.

## 판독 규칙 (extract.py 프롬프트에 반영됨)

실제 52장을 분석해 얻은 규칙입니다.

- **시트에 넣는 값은 `조회수`가 아니라 도달입니다.** 화면 라벨은 `조회한 사람` /
  `도달한 계정` / `총 시청자 수`(틱톡) 세 가지로 나타나며 전부 같은 지표입니다.
  `조회`·`조회수`는 항상 더 큰 값이며 넣으면 안 됩니다.
- 굿띵투유의 PC 웹 화면은 1만 이상을 `1.6만` 으로 축약합니다 → `reach_is_rounded`
  로 표시되고 경고가 붙습니다 (오차 ±500). 모바일 앱 화면은 정확값입니다.
- 틱톡은 `53.0K` 처럼 K 단위 반올림이라 정확값을 얻을 수 없습니다.
- 배너문구는 **썸네일 안에 박힌 글씨**입니다. 게시물 캡션이 아닙니다.

## 데이터가 흘러가는 곳

```
업로드 → 판독 → 매칭
            │
            ├─ 확정      → 「콘텐츠 대시보드 연동」 해당 날짜 열에 자동 기입
            ├─ 검토필요   → 앱 화면에서 사람이 행 지정 → 반영 → 같은 곳에 기입
            └─ (전부)    → 「_배너인사이트_자동수집」 탭에 이력 기록
```

**「_배너인사이트_자동수집」은 사람이 값을 옮기는 대기열이 아닙니다.**
판독 이력·근거를 남기는 기록용 탭입니다. 값 기입은 앱이 직접 합니다.
검토는 시트가 아니라 앱 화면에서 합니다.

## 매칭 순서

1. **채널명** — 유일하게 신뢰할 수 있는 키입니다
2. 게시일
3. 배너문구 — **보조로만** 씁니다

시트의 소재명·캡션이 채널 간에 밀려 기록된 행이 있습니다 (2026-08-21 업로드분 9건 이상).
그래서 배너문구를 1순위 키로 쓰면 엉뚱한 행으로 갑니다. 마케터에게 그 날짜 행
점검을 요청해 두면 매칭 신뢰도가 더 올라갑니다.

채널명이 거의 같으면(`laugh.34` vs `laugh.35`) 배너문구로 판단하되 `검토필요`로
표시합니다 — 업체가 라벨을 잘못 적는 경우가 실제로 있습니다.

## 비용

이미지 1장당 약 1,500 토큰. 하루 100장 / 월 3,000장 기준:

| 모델 | 월 비용 |
|---|---|
| `claude-opus-5` (기본) | 약 3만원 |
| `claude-sonnet-5` | 약 1만8천원 |
| `claude-haiku-4-5` | 약 6천원 |

`config.py` 의 `MODEL` 로 바꿉니다. 정확도가 중요한 작업이라 기본은 opus 입니다.
바꾸면 `selftest.py` 가 아니라 실제 폴더로 정확도를 다시 확인하세요.

## 아직 확인 못 한 것

**`extract.py` 는 실제 API 호출로 검증되지 않았습니다.** 제 환경에 API 키가 없었습니다.
매칭 엔진(`matcher.py`)은 45/45로 검증됐고, 사이트 화면 3종은 예외 없이 렌더링됩니다.
키를 넣고 루나앤코코 0823 폴더로 한 번 판독해 정확도를 확인한 뒤
**반영 버튼**을 쓰세요.
